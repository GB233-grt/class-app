## 部署到 Cloudflare Pages

### 方式一：控制台连 Git（推荐）

1. 代码推到 GitHub / GitLab
2. Cloudflare 控制台 → **Workers & Pages → Create → Pages → Connect to Git** → 选中仓库
3. 构建配置：

   | 项 | 值 |
   | --- | --- |
   | Framework preset | Vite（或 None） |
   | Build command | `npm run build` |
   | Build output directory | `dist` |

4. **Settings → Environment variables** 添加：

   | 变量 | 类型 |
   | --- | --- |
   | `SUPABASE_URL` | Text |
   | `SUPABASE_ANON_KEY` | Text |
   | `SUPABASE_SERVICE_ROLE_KEY` | **Secret** |

5. **Deploy**；`functions/` 会被自动识别为 Pages Functions，无需额外配置
6. （可选）**Custom domains** 绑自有域名

### 方式二：命令行

```bash
# 首次需要登录
npx wrangler login

# 构建 + 部署
npm run deploy
```

部署前记得给本地 wrangler 配好密钥（生产环境变量不会自动同步到本地）：

```bash
npx wrangler pages secret put SUPABASE_SERVICE_ROLE_KEY
```

## 验证部署成功

```bash
# 1) 前端能打开（返回 HTML，含 assets/index-*.js）
curl -s https://<你的域名>/ | head -n 5

# 2) 接口活着（未登录应返回 401 + JSON，而不是 404/500）
curl -i https://<你的域名>/api/items

# 3) 静态资源正常
curl -I https://<你的域名>/rounded-image-96.png
```

三条都符合预期，再去浏览器登录验证业务。

## 版本升级流程

```bash
# 1. 拉最新代码
git pull origin main

# 2. 看有没有新的迁移脚本
ls database/migrations

# 3. 在 Supabase SQL Editor 执行未跑过的脚本（见「数据库与迁移」）

# 4. 跑检查
npm run typecheck && npm test && npm run build

# 5. 部署
npm run deploy
```

> **顺序很重要**：先升级数据库，再部署代码。
> 反过来会出现「新代码访问旧表结构」，报字段不存在。

## 回滚

### 回滚代码

Cloudflare 控制台 → 你的 Pages 项目 → **Deployments** → 找到上一个成功的部署 → **Rollback**（秒级生效，不用重新构建）。

用 Git 回滚再重新部署也可以：

```bash
# 找到要回退到的提交
git log --oneline -10

# 生成一个反向提交（推荐，保留历史）
git revert <commit-sha>
git push origin main
```

### 回滚数据库

迁移脚本**不提供自动回滚**，只能靠备份。所以：

- 执行破坏性脚本（改约束、删列）前，先在 Supabase **Database → Backups** 确认有可用备份
- 或者先 `pg_dump` 一份（命令见 [[数据库与迁移#备份与恢复]]）
- 真出问题时：新建一个 Supabase 项目恢复备份 → 改环境变量指向它 → 重新部署

### 回滚 wiki 页面

Wiki 独立于代码仓库，有自己的提交历史：

```bash
# 克隆 wiki 仓库
git clone https://github.com/GB233-grt/class-app.wiki.git
cd class-app.wiki

# 看历史
git log --oneline

# 把某个页面恢复到旧版本
git checkout <commit-sha> -- Home.md
git commit -m "revert: Home 恢复到 <commit-sha>"
git push
```

也可以在网页上：Wiki 页面右上角 **History** → 选旧版本 → **Revert**。

## 日常维护

| 频率 | 事项 |
| --- | --- |
| 每周 | 看一次 Supabase **Database → Usage**，确认没逼近免费额度 |
| 每月 | 检查 Cloudflare 构建日志有没有警告 |
| 每学期 | 备份一次数据；清理测试账号；核对 `students` 名单 |
| 按需 | 商品到期自动下架依赖有人访问列表触发 —— 长期无人访问时，进后台刷新一次商品管理页即可 |

### 健康检查 SQL

```sql
-- 余额与积分明细是否一致（正常应返回 0 行）
select s.id, s.name, s.points, l.balance_after
from students s
join (
  select distinct on (student_id) student_id, balance_after
  from points_ledger
  order by student_id, created_at desc, id desc
) l on l.student_id = s.id
where s.points <> l.balance_after;

-- 已过期但仍是上架状态的商品（正常应返回 0 行）
select id, name, expires_at
from items
where is_active and expires_at is not null and expires_at <= now();

-- 库存为 0 却仍在售的商品
select id, name, stock, type
from items
where is_active and stock = 0;
```

第一条如果查出数据，说明历史上有过扣分异常，执行 `select expire_items();` 与 `database/migrations/13_allow_zero_cost_items.sql` 后再核对。

## 成本

| 服务 | 免费额度 | 本项目实际占用 |
| --- | --- | --- |
| Cloudflare Pages | 无限带宽、500 次构建/月 | 每次 `npm run deploy` 算 1 次 |
