# 开发与贡献

---

## 本地开发环境

```bash
git clone https://github.com/GB233-grt/class-app.git
cd class-app
npm install

cp .env.example .env
cp .dev.vars.example .dev.vars
```

启动（两个终端，带热更新）：

```bash
npm run pages:dev    # 终端 1：本地 Functions :8788
npm run dev          # 终端 2：Vite :5173（/api 代理到 8788）
```

只跑一次看效果：

```bash
npm run pages:dev    # 构建 + 静态预览 :8788
```

---

## 提交前必须跑的三条

```bash
npm run typecheck    # TypeScript（前端 + Functions 两套 tsconfig）
npm test             # Vitest 单元测试
npm run build        # 生产构建
```

CI 会重复跑同样的检查（`.github/workflows/ci.yml`），本地通过可以省一轮等待。

## 测试

### 单元测试

```bash
npm test           # 跑一次
npm run test:watch # 监听模式
```

当前覆盖：`src/lib/validation.test.ts`（表单校验、密码强度）、`src/lib/utils.test.ts`（格式化、日期时间往返转换），共 40 个用例。

新增测试放在同目录，命名 `*.test.ts`。

### 数据库函数测试

`database/tests/redeem_item.test.sql` —— 复制整个文件到 Supabase **SQL Editor** 执行，事务内运行并自动回滚。

预期输出：

```text
DO
ROLLBACK
```

扩展现有测试或新增函数时，照这个结构写：`begin;` → 造数据 → `do $$ ... $$` 断言 → `rollback;`。

## 目录结构

```text
├── database/
│   ├── migrations/     # 增量迁移 01 → 14（只增不改）
│   ├── all-in-one/     # 全新库一键建表 + 种子
│   ├── tests/          # 数据库函数测试（事务 + 回滚）
│   └── seed/           # 种子模板
├── functions/          # Cloudflare Pages Functions（后端）
│   ├── api/            # 路由：auth / items / students / redemptions / ledger / user / admin
│   └── lib/            # 鉴权、HTTP 工具、Supabase 客户端工厂
├── src/                # 前端
│   ├── api/            # Fetch 客户端与接口定义
│   ├── components/     # common / layout / feature 三层
│   ├── hooks/          # 数据与状态
│   ├── lib/            # 校验、常量、工具函数（含测试）
│   ├── pages/          # 三个仪表盘 + 登录页
│   └── types/
├── tools/              # 本地预览服务器、Wiki 发布脚本
└── wiki/               # 本 Wiki 的源文件
```

**分层原则**：前端 `api 客户端 → hooks → 组件`，后端 `路由 → 中间件（鉴权） → Supabase 客户端工厂`。改业务优先动最上层的组件，别跨层。

## 分支与提交规范

分支：

```text
feat/短描述
fix/短描述
docs/短描述
refactor/短描述
```

提交信息遵循 [Conventional Commits](https://www.conventionalcommits.org/)：

```text
feat: 商品支持按到期时间自动下架
fix: 网络商品兑换后未扣减库存
docs: 补充 Windows 下的环境变量复制命令
```

一条提交只做一件事。

## 数据库变更规则

1. **只增不改**：已发布的迁移脚本不要修改，新增 `NN+1_xxx.sql`
2. 必须可重复执行：`IF NOT EXISTS` / `DROP POLICY IF EXISTS` / `CREATE OR REPLACE`
3. 重写函数时，在文件头注明「是否已包含之前脚本的修复」
4. 同步更新 `database/all-in-one/step1-schema.sql`
5. 补上数据库测试场景

## 提 PR

1. Fork → 从 `main` 切分支
2. 完成改动，跑通三条检查
3. 按模板填写：解决了什么、影响范围、怎么验证的
4. UI 改动附前后截图
5. Review 通过后合并

**第一次参与？** 带 [`good first issue`](https://github.com/GB233-grt/class-app/labels/good%20first%20issue) 标签的 Issue 是刻意留出的入门任务，直接回「我来试试」即可。

## 改 Wiki

Wiki 页面源文件在 `wiki/` 目录，改完执行：

```bash
npm run wiki:publish
```

脚本会克隆 wiki 仓库、同步 `wiki/*.md`、提交并推送。

> 首次使用前，需要先在网页上创建 Wiki 的第一页（GitHub 不提供创建 Wiki 的 API）：打开
> <https://github.com/GB233-grt/class-app/wiki> → **Create the first page** → 随便填点内容保存。
> 之后 `npm run wiki:publish` 就能覆盖成正式内容了。

新增页面：在 `wiki/` 下新建 `页面名.md`，并在 `wiki/_Sidebar.md` 里加一行 `- [[页面名]]`。

### 敏感信息

**不要**在 Wiki 里写：Supabase key、数据库密码、真实学生姓名学号、内网地址。
Wiki 是公开的，**历史记录也公开** —— 写错的密钥即使删掉也能翻出来，只能重置密钥止损。

## 代码风格

- TypeScript 严格模式，避免 `any`
- 函数组件 + Hooks，业务逻辑放 `src/hooks/`
- 样式统一 Tailwind 原子类
- 注释与界面文案用中文
- 组件按 `common` / `layout` / `feature` 三层放置
