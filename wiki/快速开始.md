# 快速开始

从零到能登录，大约 5 分钟。全程只需要三条命令 + 两段 SQL。

> **前置条件**：Node.js ≥ 18、一个 Supabase 项目（免费版够用）、一个 Cloudflare 账号（仅部署时需要）。

---

## 1. 拉代码、装依赖

```bash
git clone https://github.com/GB233-grt/class-app.git
cd class-app
npm install
```

检查版本：

```bash
node -v      # 需要 >= 18
npm -v
```

---

## 2. 配置环境变量

```bash
cp .env.example .env
cp .dev.vars.example .dev.vars
```

Windows PowerShell 用：

```powershell
Copy-Item .env.example .env
Copy-Item .dev.vars.example .dev.vars
```

然后填这两个文件（字段含义见 [[配置参考]]）：

**`.env`**（前端，构建时注入浏览器）

```dotenv
VITE_SUPABASE_URL=https://<你的项目>.supabase.co
VITE_SUPABASE_ANON_KEY=<anon key>
```

**`.dev.vars`**（本地后端）

```dotenv
SUPABASE_URL=https://<你的项目>.supabase.co
SUPABASE_ANON_KEY=<anon key>
SUPABASE_SERVICE_ROLE_KEY=<service_role key>
```

密钥位置：Supabase 控制台 → **Project Settings → API**。

> ⚠️ `SUPABASE_SERVICE_ROLE_KEY` 是服务角色密钥，**只能**放在 `.dev.vars` 或 Cloudflare 环境变量里。
> 两个文件都已在 `.gitignore` 中，不要手动提交。

---

## 3. 初始化数据库

打开 Supabase 控制台 → **SQL Editor** → **New query**，依次粘贴执行：

| 顺序 | 文件 | 作用 |
| --- | --- | --- |
| 1 | `database/all-in-one/step1-schema.sql` | 建表 + 原子函数 + 行级安全（RLS） |
| 2 | `database/all-in-one/step2-seed.sql` | 示例商品与积分数据 |

每个文件执行完，控制台底部应显示 `Success. No rows returned` 或类似提示，**没有红色报错**。

> 已有数据库（不是全新库）请走增量升级，见 [[数据库与迁移#增量升级已有数据库]]。

验证建表结果，在 SQL Editor 里跑：

```sql
select table_name
from information_schema.tables
where table_schema = 'public'
order by table_name;
```

应能看到：`items`、`points_ledger`、`redemptions`、`students`、`system_settings`。

---

## 4. 创建登录账号

进入 Supabase 控制台 → **Authentication → Users → Add user**：

| 角色 | 邮箱 | 说明 |
| --- | --- | --- |
| 管理员 | `admin@school.edu` | 对应 seed 里的管理员记录 |
| 学生 | `student@school.edu` | 示例学生 1 |
| 学生 | `student2@school.edu` | 示例学生 2 |

填写时**务必勾选 `Auto Confirm User`**，否则登录会提示「邮箱尚未验证」。

> 邮箱必须和 `database/seed/` 里的模板一致 —— 模板通过邮箱子查询把 `students.id` 对齐到 `auth.users.id`。
> 想用自己的邮箱，就先改模板再执行。

---

## 5. 启动

```bash
npm run pages:dev
```

打开 <http://localhost:8788>，用第 4 步创建的账号登录。

需要前端热更新时，开两个终端：

```bash
# 终端 1：本地 Functions
npm run pages:dev

# 终端 2：Vite（/api 自动代理到 8788）
npm run dev
```

然后访问 <http://localhost:5173>。

---

## 6. 冒烟测试

登录成功后，按顺序点一遍，能走完说明环境没问题：

- [ ] 学生端能看到积分余额和商品卡片
- [ ] 兑换一个商品，积分扣减、兑换记录新增一条
- [ ] 「积分明细」里能看到这笔扣分
- [ ] 管理员登录 → 商品管理能看到同款商品
- [ ] 管理员加一次积分，学生端刷新后余额变多

也可以用命令行验证后端是否活着：

```bash
curl -i http://localhost:8788/api/items
```

预期返回 `401` 和 `{"error":"未登录或登录状态已失效"}` —— **能返回 JSON 就说明 Functions 起来了**，401 是正常的。

## 7. 常用命令

```bash
npm run dev          # 仅前端热更新（API 需另开 pages:dev）
npm run build        # 构建到 dist/
npm run typecheck    # TypeScript 类型检查（前端 + Functions）
npm test             # 单元测试（Vitest）
npm run pages:dev    # 前端 + 本地 API（:8788）
npm run deploy       # 构建并部署到 Cloudflare Pages
```
