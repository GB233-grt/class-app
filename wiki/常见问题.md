## 登录相关

### 提示「邮箱或密码错误」

```sql
-- 确认账号存在且已确认邮箱
select id, email, email_confirmed_at, created_at
from auth.users
where email = 'student@school.edu';
```

`email_confirmed_at` 为 `NULL` 表示没确认 → Supabase 控制台 → **Authentication → Users** → 该用户 → 确认邮箱。

### 提示「用户资料不存在」

登录成功但 `students` 表里没有对应记录。两种修法：

```sql
-- ① 手动补一条（把邮箱换成你的）
insert into students (id, name, email, role, points)
select id, '你的名字', email, 'student', 0
from auth.users where email = 'your@school.edu';
```

② 或执行种子模板：`database/seed/01_create_admin.sql`、`02_create_students.sql`。

### 改了密码，旧密码忘了

走「忘记密码」流程发重置邮件；没配 SMTP 时，在 Supabase 控制台 → **Authentication → Users** → 该用户 → 直接设新密码。

### 登录后立刻被踢回登录页

令牌失效。打开浏览器控制台看 Network：

- `/api/auth/me` 返回 401 → 账号在 `auth.users` 被删了，或 `students` 记录被删
- 返回 500 → 后端缺少 `SUPABASE_SERVICE_ROLE_KEY`，见 [[配置参考#后端变量]]

清理一下本地会话再试（浏览器控制台执行）：

```js
localStorage.removeItem('spe_session')
```

## 本地开发

### 接口 404

`npm run dev` 只启动前端，**不带后端**。要么另开一个终端跑 `npm run pages:dev`，要么直接用 8788 端口。

```bash
# 终端 1
npm run pages:dev

# 终端 2
npm run dev
```

### 端口被占用

```bash
# Windows
netstat -ano | findstr :8788
taskkill /PID <pid> /F

# macOS / Linux
lsof -i :8788
kill -9 <pid>
```

### 改了代码页面没变化

`npm run pages:dev` 是「构建 + 静态预览」，不会热更新。要么重新跑一次，要么用 `npm run dev`（5173）配 `pages:dev` 的 API。

## 兑换与积分

### 提示「积分不足」

学生余额不够。管理员 → 学生管理 → 加分。

### 提示「库存不足，仅剩 N 件」

库存扣到 0 了。管理员 → 商品管理 → 编辑 → 调大库存。

### 兑换成功了但积分没扣

这是 **v1.0.0 之前**的已知缺陷（网络商品分支漏了扣分）。修复方法：

```sql
-- 确认函数版本：已修复的版本里，digital 分支有 UPDATE students 语句
select prosrc from pg_proc where proname = 'redeem_item';
```

看不到 `UPDATE students SET points` 就说明要执行 `database/migrations/13_allow_zero_cost_items.sql`。

### 历史数据对不上怎么办

```sql
-- ① 先看哪些学生对不上
select s.name, s.points as 实际余额, l.balance_after as 按明细应为
from students s
join (
  select distinct on (student_id) student_id, balance_after
  from points_ledger order by student_id, created_at desc, id desc
) l on l.student_id = s.id
where s.points <> l.balance_after;

-- ② 确认无误后再对齐（会覆盖 students.points）
update students s set points = l.balance_after
from (
  select distinct on (student_id) student_id, balance_after
  from points_ledger order by student_id, created_at desc, id desc
) l
where s.id = l.student_id and s.points <> l.balance_after;
```

> 前提是「所有积分变动都经过数据库函数」。如果你曾直接在库里改过 `students.points`，先人工核对再执行。

## 商品相关

### 网络商品提示「该商品未配置下载链接」

管理员 → 商品管理 → 编辑该商品 → 填「下载链接」→ 保存。

### 网络商品的「库存」和「下载次数限制」有什么区别

| 字段 | 作用 | 现状 |
| --- | --- | --- |
| `库存数量` | 该商品能被兑换几次，兑完售罄 | ✅ 生效 |
| `下载次数限制` | 每个学生最多下载几次 | ⚠️ **仅保存，未生效** |

`download_limit` 目前没有计数的下载代理接口，学生拿到的是原始链接。要真正限制需实现 `/api/downloads/:redemptionId`。

### 设置了到期时间，为什么还在「已上架」

到期清理是**惰性**的：只有人访问商品列表或发起兑换时才触发。刷新一次商品管理页即可。

也可以手动触发：

```sql
select expire_items();
```

### 商品下架了，学生还能看到吗

不能。学生接口只返回 `is_active = true` 的商品。
但**已兑换的记录不受影响**，学生仍能在「兑换记录」里看到历史。

## 学生自助修改资料

### 学生改不了昵称 / 学号

默认是**关闭**的。开启方式：管理员 → 系统设置 → 「允许自助修改昵称 / 学号」→ 打开 → 保存。

对应数据库记录：

```sql
select * from system_settings where key = 'allow_profile_edit';
-- 期望 value = {"enabled": true}
```

### 提示「数据库尚未升级：请执行 ..._system_settings.sql」

系统配置表不存在，执行 `database/migrations/10_system_settings.sql`。

## 部署相关

### 构建成功但页面 404 / 白屏

- 检查 Build output directory 是否为 `dist`
- 检查 `index.html` 里的资源路径是否带 hash 且能访问：

```bash
curl -I https://<域名>/assets/index-xxxx.js
```

### 接口全部 500

八成是环境变量问题：

```bash
# 用 wrangler 查看当前项目的环境变量名（不显示值）
npx wrangler pages deployment list
```

去 **Settings → Environment variables** 确认三个变量都在，`SERVICE_ROLE_KEY` 类型是 Secret。

### 部署后要不要重新跑 SQL

看这次改动有没有碰 `database/`。只改前端/后端代码不需要；新增迁移脚本则需要。
