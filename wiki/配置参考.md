# 配置参考

所有可配置项集中在本页。**填值示例一律用占位符，不要把真实密钥贴到任何文档里。**

---

## 前端变量（`.env`）

浏览器构建时由 Vite 注入，属于公开信息。

| 变量 | 必填 | 类型 | 示例 | 说明 |
| --- | --- | --- | --- | --- |
| `VITE_SUPABASE_URL` | ✅ | string | `https://<project>.supabase.co` | Supabase 项目 URL |
| `VITE_SUPABASE_ANON_KEY` | ✅ | string | `<anon key>` | 匿名称密钥，可公开 |

获取路径：Supabase 控制台 → **Project Settings → API → Project URL / anon public**。

---

## 后端变量

本地放 `.dev.vars`，生产放 Cloudflare 环境变量。

| 变量 | 必填 | 类型 | 示例 | 说明 |
| --- | --- | --- | --- | --- |
| `SUPABASE_URL` | ✅ | string | `https://<project>.supabase.co` | 同上 |
| `SUPABASE_ANON_KEY` | ✅ | string | `<anon key>` | 同上 |
| `SUPABASE_SERVICE_ROLE_KEY` | ✅ | **secret** | `<service_role key>` | 仅后端使用，可绕过 RLS |

获取路径：Supabase 控制台 → **Project Settings → API → service_role**。

### 生产环境怎么填

Cloudflare 控制台 → 你的 Pages 项目 → **Settings → Environment variables**：

| 变量 | 类型 | 备注 |
| --- | --- | --- |
| `SUPABASE_URL` | Text（明文） | 公开信息 |
| `SUPABASE_ANON_KEY` | Text（明文） | 公开信息 |
| `SUPABASE_SERVICE_ROLE_KEY` | **Secret（加密）** | 必须选 Secret，不要用 Text |

命令行也可以设置（wrangler v3）：

```bash
npx wrangler pages secret put SUPABASE_SERVICE_ROLE_KEY
```

---

## ⚠️ 安全红线

| 不要做 | 后果 |
| --- | --- |
| 把 `service_role` 写进 `.env`（前端变量） | 密钥随构建产物发到浏览器，等于公开 |
| 把密钥提交进 Git / 写进 Issue / 写进 Wiki | 历史记录永久可查，只能换 key 止损 |
| 在截图里露出密钥或真实学生姓名 | 同上 |

万一泄露了：Supabase 控制台 → **Project Settings → API → Reset** 重新生成，然后更新 `.dev.vars` 与 Cloudflare Secret，重新部署。

## 代码内可调参数

| 位置 | 参数 | 默认值 | 改法 |
| --- | --- | --- | --- |
| `src/lib/constants.ts` | `POINT_REASONS` | 一组常见加分原因 | 直接往数组里追加，无需迁移 |
| `src/lib/validation.ts` | `passwordStrengthExp` | 8 位 + 大小写 + 数字 + 特殊字符 | 改正则后，**同步改** `functions/api/auth/change-password.ts` 里的同名规则 |
| `src/lib/validation.ts` | `itemFormSchema` | 商品名 ≤ 50、描述 ≤ 200 | 与后端 `requireString(..., { max })` 保持一致 |
| `database/migrations/01_create_students.sql` | `points >= 0` | 积分不允许为负 | 改约束需新增迁移脚本 |

> 前端校验和后端校验是两套独立实现，改规则时**两边都要改**，只改前端等于没改。

## 时间与日期

| 概念 | 存储 | 展示 |
| --- | --- | --- |
| `items.expires_at` | `timestamptz`（UTC） | 前端转本地时区显示 |
| `redemptions.created_at` | `timestamptz`（UTC） | 同上 |
| 表单里的「到期时间」 | `<input type="datetime-local">` 本地时间 | 提交前用 `fromDateTimeLocalValue()` 转 ISO |

相关工具函数：`src/lib/utils.ts` 的 `toDateTimeLocalValue` / `fromDateTimeLocalValue`，已有单元测试覆盖往返转换。

## 环境变量速查

```bash
# 查看本地是否配好（不会打印值）
node -e "require('dotenv').config(); console.log(['VITE_SUPABASE_URL','VITE_SUPABASE_ANON_KEY'].map(k=>k+'='+(process.env[k]?'已配置':'缺失')).join('\n'))"
```

> 项目没有安装 `dotenv`，上面只是通用写法；本地实际由 Vite / wrangler 自动读取，无需手动加载。

更简单的方式是直接检查文件是否存在且非空：

```bash
# macOS / Linux
grep -c . .env .dev.vars

# Windows PowerShell
Get-Content .env | Measure-Object -Line
Get-Content .dev.vars | Measure-Object -Line
```
